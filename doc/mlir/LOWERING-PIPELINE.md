# MLIR Lowering Pipeline

**Related:** [../MLIR-COMPILATION-OVERVIEW.md](../MLIR-COMPILATION-OVERVIEW.md)

---

## Overview

This document provides a high-level overview of the transformation stages as ONNX models are lowered through MLIR dialects to native code. For detailed pass implementations, see the individual pass documents in [`passes/`](passes/).

---

## Pipeline Stages

```
ONNX-MLIR        →        HIP Dialect      →      LLVM Dialect     →    Native Code
(MorphiZen)           (OnnxToHip pass)        (HipToLLVM pass)       (LLVM backend)
                                            (GenerateInterface pass)
```

---

## Pass Details

### Stage 1: ONNX-MLIR (Input from MorphiZen)

**Input:** ONNX model file (`.onnx`)
**Output:** MLIR module with ONNX dialect, func, arith
**Generated by:** MorphiZen framework (existing)

**Key characteristics:**
- High-level ONNX operations (`onnx.Conv`, `onnx.Relu`, etc.)
- Tensor types (`tensor<...>`)
- Constants inlined in code (`arith.constant`)
- Return value semantics

**Example:**
```mlir
module {
  func.func @main(%arg0: tensor<1x3x224x224xf32>) -> tensor<1x64x224x224xf32> {
    %weights = arith.constant dense<[...]> : tensor<64x3x3x3xf32>
    %bias = arith.constant dense<[...]> : tensor<64xf32>

    %0 = "onnx.Conv"(%arg0, %weights, %bias) {
      kernel_shape = [3, 3],
      strides = [1, 1],
      pads = [1, 1, 1, 1]
    } : (tensor<...>, tensor<...>, tensor<...>) -> tensor<...>

    %1 = "onnx.Relu"(%0) : (tensor<...>) -> tensor<...>

    return %1 : tensor<...>
  }
}
```

---

### Stage 2: HIP Dialect - OnnxToHip Pass

**See:** [passes/OnnxToHip.md](passes/OnnxToHip.md) for complete details

**Key transformations:**
1. Add module I/O metadata attributes (input/output counts and ranks)
2. Extract constants to `llvm.mlir.global`
3. Convert ONNX operations → HIP operations
4. Change @main signature (add context, output arg, i32 return)
5. Generate constant management helpers

**Example output:**
```mlir
module attributes {
  hipdnn.input_count = 1 : i64,
  hipdnn.input_ranks = dense<[4]> : tensor<1xi64>
} {
  llvm.mlir.global constant @constant_0(...)

  func.func @main(%ctx: !hip.context,
                   %input: memref<...>,
                   %output: memref<...>) -> i32 {
    %weights = hip.get_constant(%ctx, 0)
    %temp = hip.alloc(%ctx)
    hip.conv(%ctx, %input, %weights, %bias, %temp) {...}
    memref.copy %temp, %output
    return %c0 : i32
  }

  llvm.func @get_constant_count() -> i64
  func.func @initialize_constants(%ctx: !hip.context) -> i32
  func.func @release_constants(%ctx: !hip.context) -> i32
}
```

---

### Stage 3: LLVM Dialect - HipToLLVM Pass

**See:** [passes/HipToLLVM.md](passes/HipToLLVM.md) for complete details

**Key transformations:**
1. Generate wrapper functions for MIOpen/hipBLAS calls
2. Transform @main to use memref struct arrays
3. Lower !hip.context → !llvm.ptr
4. Convert HIP operations to wrapper calls
5. Lower constant helpers to LLVM

**Example output:**
```mlir
module attributes {
  hipdnn.input_count = 1 : i64,
  hipdnn.input_ranks = dense<[4]> : tensor<1xi64>
} {
  // Wrapper function for hip.conv
  llvm.func @hip_conv_wrapper(%ctx: !llvm.ptr,
                               %input: !llvm.struct<...>,
                               %weights: !llvm.struct<...>,
                               ...) -> i32 {
    // Extract RUNTIME dimensions from memref structs
    %input_n = llvm.extractvalue %input[3, 0]  // Runtime!
    // Call MIOpen with runtime dimensions
    llvm.call @miopenConvolutionForward(...)
  }

  // @main transformed to use memref struct arrays
  llvm.func @main(%context: !llvm.ptr,
                  %inputs: !llvm.ptr,   // Array of memref structs
                  %outputs: !llvm.ptr)  // Array of memref structs
                  -> i32 {
    %input_0 = [load from inputs[0]]
    llvm.call @hip_conv_wrapper(%context, %input_0, ...)
  }

  llvm.func @initialize_constants(%context: !llvm.ptr) -> i32 {
    %addr = llvm.mlir.addressof @constant_0
    llvm.call @hipMalloc(...)
    llvm.call @hipMemcpy(...)
  }
}
```

**Critical:** Wrappers extract dimensions at runtime (supports dynamic shapes!)

---

### Stage 4: C Interface - GenerateInterfacePass

**See:** [passes/GenerateInterfacePass.md](passes/GenerateInterfacePass.md) for complete details

**Key transformations:**
1. Generate `inference_init` - Allocates context, creates handles, uploads constants
2. Generate `inference_compute` - Parses span_t, builds memrefs with **runtime dimensions**, calls @main
3. Generate `inference_cleanup` - Frees resources, destroys handles

**Example output:**
```mlir
llvm.func @inference_init(%out_state: !llvm.ptr<!llvm.ptr>) -> i32 {
  %context = llvm.call @malloc(...)
  llvm.call @hipStreamCreate(...)
  llvm.call @miopenCreate(...)
  %gpu_constants = llvm.call @malloc(...)
  llvm.call @initialize_constants(%context)
  llvm.store %context, %out_state
  llvm.return %c0 : i32
}

llvm.func @inference_compute(%state: !llvm.ptr,
                              %inputs: !llvm.ptr,  // span_t*
                              %outputs: !llvm.ptr) -> i32 {
  // Validate counts and ranks
  // Load RUNTIME dimensions from tensor_t.shape
  %dim0 = llvm.load %shape_ptr[0]  // Runtime!
  %dim1 = llvm.load %shape_ptr[1]  // Runtime!
  // Calculate RUNTIME strides
  %stride0 = llvm.mul %dim1, %stride1  // Runtime!
  // Build memref struct with runtime values
  %memref = [build with runtime dims]
  // Call @main
  llvm.call @main(%state, %input_array, %output_array)
}

llvm.func @inference_cleanup(%state: !llvm.ptr) -> i32 {
  llvm.call @release_constants(%state)
  llvm.call @hipblasLtDestroy(...)
  llvm.call @free(%state)
}
```

**Critical:** This pass implements dynamic shape support by loading dimension values at runtime!

---

### Stage 5: Native Code (LLVM Backend)

**Input:** LLVM dialect module
**Output:** Native DLL

**Steps:**
1. Translate LLVM dialect → LLVM IR (`.ll`)
2. Compile LLVM IR → Object file (`.obj` / `.o`)
3. Link with HIP/MIOpen/hipBLAS → DLL (`.dll` / `.so`)

**Exported symbols:**
- `inference_init`
- `inference_compute`
- `inference_cleanup`

## Data Flow Through Pipeline

### Constants

```
ONNX proto
  ↓ (OnnxToHip)
llvm.mlir.global
  ↓ (compile to DLL)
DLL .data section
  ↓ (inference_init)
GPU memory
  ↓ (inference_compute)
Used in @main via hip_get_constant
```

See [CONSTANT-MANAGEMENT.md](CONSTANT-MANAGEMENT.md)

### Dynamic Shapes

```
User: tensor_t.shape = [2, 3, 256, 256]
  ↓ (inference_compute)
Load runtime dimensions: [2, 3, 256, 256]
  ↓
Calculate runtime strides: [196608, 65536, 256, 1]
  ↓
Build memref struct with runtime values
  ↓ (@main)
Pass to wrappers
  ↓ (hip_conv_wrapper)
Extract dimensions: llvm.extractvalue (runtime!)
  ↓
Pass to MIOpen: miopenSet4dTensorDescriptor(N, C, H, W)
```

See [../DYNAMIC-SHAPE-DESIGN.md](../DYNAMIC-SHAPE-DESIGN.md)

## Pass Dependencies

```
OnnxToHip
  ├─ Generates: @main, constant helpers, module metadata
  └─ Prerequisite for: HipToLLVM

HipToLLVM
  ├─ Requires: @main, constant helpers
  ├─ Generates: Wrappers, transformed @main
  └─ Prerequisite for: GenerateInterfacePass

GenerateInterfacePass
  ├─ Requires: @main (final signature), constant helpers, module metadata
  └─ Generates: inference_init/compute/cleanup
```

---

## Key Design Principles

1. **Inline lowering**: All operations lowered inline within @main
2. **Explicit state**: Context passed as parameter
3. **Dynamic shapes from Day 1**: Dimensions loaded at runtime
4. **Two-layer architecture**: C interface wraps internal functions
5. **Pattern-based**: Uses MLIR conversion framework
